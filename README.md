# Weather Wardrobe — PWA

Один статичный `index.html` + service worker + Vercel-функции в `api/` (без зависимостей и без сборки).
Образ на день подбирает встроенный алгоритм: погода, ваш гардероб, цвета, стили и предпочтения. ИИ и платных ключей нет.

## Что внутри
- Погода: Apple WeatherKit (если настроен) или Open-Meteo, почасовой и дневной прогноз.
- Подбор образа на весь день: слои, обувь, верхняя одежда, дождь, ветер, комфортный диапазон температур, цвета и совместимость стилей, история, коллаж из фото.
- Определение цвета по пикселям фото и стиля по эвристикам, всё на устройстве.
- Необязательный вход Google для синхронизации между устройствами. Без входа всё работает, данные хранятся на устройстве.

## Выбор гардероба
Если в гардеробе нет вещей, на главной показан выбор: отметьте картинки, похожие на ваши вещи (`demo/*.webp`, список `DEMO` в `index.html`). Есть «Выбрать все» и «Снять все отметки», повторное нажатие на вещь снимает отметку.
Кнопка «Добавить в гардероб (N)» добавляет отмеченное в ваш гардероб как обычные вещи (с вырезанным фоном, их можно править и удалять), и только после этого подбирается образ.
Если гардероб не пуст, но в нём нет целой группы (обувь, низ, верх, верхняя одежда), недостающее подставляется как демо-образец только для этой группы: он помечен, не добавляется в гардероб, и образ с ним нельзя сохранить.

## Фото вещей
Ваши фото показываются крупно на стеклянных плитках, коллаж тоже на стеклянном фоне. Фон фото сам не вырезается. По желанию кнопка «Вырезать фон» в форме вещи (и «Вырезать фон у всех вещей» в настройках) делает это на устройстве без ИИ. Работает только на ровном фоне. «Вернуть исходные фото» в настройках возвращает оригиналы (они хранятся только на том устройстве, где вещь добавлена).

## Переменные окружения
См. `.env.example`. На Vercel: Settings → Environment Variables → **Redeploy**. Всё необязательно.

| Переменная | Назначение |
|---|---|
| `GOOGLE_CLIENT_ID`, `SESSION_SECRET` | вход Google для синхронизации |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | Upstash Redis, хранилище для синхронизации |
| `VERIFIED_NICKS` | ники с синей галочкой в Driply через запятую, напр. `kk1cher9` (после смены нужен Redeploy) |
| `APPLE_TEAM_ID`, `APPLE_SERVICE_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` | WeatherKit |

## Vercel
1. Папка проекта → GitHub → Import в Vercel (Framework Preset: Other).
2. Если нужна синхронизация: Storage → Upstash Redis и переменные выше. **Redeploy**.

## Языки и офлайн

- Язык интерфейса: русский / українська / English. По умолчанию берётся из языка браузера (uk → украинский, en → английский, остальное → русский); меняется в Настройки → «Язык» и запоминается. Перевод живёт в `i18n.js` (словарь + шаблоны фраз), внутренние значения (категории, стили) остаются английскими, поэтому смена языка ничего не ломает в сохранённых данных.
- Офлайн: service worker при первом запуске скачивает все 41 демо-картинку (~1 МБ) вместе с оболочкой приложения (`wardrobe-v29`). Если добавляете файлы в `demo/`, добавьте их в список `DEMO` в `sw.js` и поднимите версию кэша.

## Driply — соцсеть образов (вкладка между «Гардероб» и «Образы»)
Файлы: `social.js` (интерфейс), `api/social.js` (весь backend одной функцией), `tests/social.test.js`, `tests/browser/e2e_social.py`.

**Нужно для работы:** `GOOGLE_CLIENT_ID`, `SESSION_SECRET` и Upstash Redis / Vercel KV (`KV_REST_API_URL`, `KV_REST_API_TOKEN`) — те же, что для синхронизации. Без них вкладка показывает пояснение, а остальное приложение работает как раньше. Отдельной авторизации нет: профиль привязан к Google-аккаунту.

**Миграции БД:** SQL-миграций нет — используется Redis. Схема ключей `wd:s:*`: `prof:<sub>`, `nick:<ник>` (уникальность через SET NX), `post:<id>`, `img:<id>`/`th:<id>` (фото и миниатюра), `feed`, `uposts:<sub>`, `hot` (тренды), `likes:<id>`, `savers:<id>`, `cm:<id>`, `following:<sub>`/`followers:<sub>`, `saved:<sub>`, `aff:<sub>` (стили для «Для вас»), `nz:<sub>`/`nh:<sub>` (уведомления). Лайки/подписки — множества, дублей быть не может. Ничего выполнять не нужно.

**Безопасность:** все действия проверяются на сервере (сессия + CSRF-заголовок); править/удалять можно только свои посты и комментарии; фото проверяются по сигнатуре (jpeg/png/webp), ≤600 КБ, миниатюра ≤90 КБ, лимит 30 постов/сутки; ответы API не содержат email и внутренние id аккаунтов. Клиент сжимает фото до 1080 px (WebP).

**Ограничения:** фото хранятся в Redis (для больших объёмов лучше вынести в Vercel Blob/S3 — меняется только запись/чтение `img:*`); поиск по никам сканирует набор ников (хорошо до тысяч пользователей); черновики хранятся только на устройстве; нет жалоб/модерации, ЛС и хештегов (структура готова к расширению); приложение Capacitor (`app/`) подключается к тому же серверу только если указан его адрес.

**Истории (24 часа):** кольца над лентой Driply — свои и тех, на кого вы подписаны. Просмотр на весь экран: тап справа/слева — следующая/предыдущая, удержание — пауза, свайп вниз — закрыть; автор видит счётчик и список просмотревших и может удалить. Ключи Redis: `story:<id>`, `simg:<id>` (фото ≤420 КБ), `ustories:<sub>`, `sviews:<id>`; истории скрываются через 24 ч (и истекают в Redis через 25 ч), видны только подписчикам и автору.

**Навигация:** в нижней панели 4 вкладки (Главная, Гардероб, Driply, Образы). Общие настройки приложения открываются из Driply → свой профиль → значок «три полоски» вверху справа (там же кнопка есть на экране входа Driply, чтобы настройки были доступны и без входа). Чтобы вернуть «Настройки» в нижнюю панель, добавьте `['settings','gear','Settings']` в `NT` и `'settings'` в `TABS` в `index.html`.

## Сообщения (вкладка «Чаты»)
Файлы: `chat.js` (интерфейс), `api/dm.js` (backend), `tests/dm.test.js`, `tests/browser/e2e_chat.py`. Те же переменные окружения и тот же Redis, что у Driply; нужен профиль Driply (ник).

Возможности: личные диалоги 1-на-1, текст и фото (сжимаются на устройстве, ≤500 КБ), непрочитанные (счётчик на вкладке и в списке), статусы «Отправляется / Отправлено / Просмотрено», удаление своих сообщений у обоих, блокировка пользователя, новый чат по поиску, кнопка «Написать» в чужом профиле, догрузка истории, повтор при ошибке отправки. Обновление «почти в реальном времени» через опрос (чат открыт — каждые ~2,5 с, список — 6 с, значок — 25 с): на Vercel нет постоянных соединений; для настоящего push-режима позже можно подключить Pusher/Ably/Upstash Realtime без смены интерфейса.

Ключи Redis `wd:m:*`: `conv:<cid>` (участники, последнее сообщение), `msg:<cid>` (hash id→сообщение), `msgs:<cid>` (zset по времени), `img:<cid>:<id>` (фото), `inbox:<sub>` (zset диалогов), `unread:<sub>` (hash cid→число), `read:<cid>` (когда каждый прочитал), `blocked:<sub>`. Идентификатор диалога — непрозрачный хеш двух аккаунтов; чужой диалог отвечает 404, фото доступны только двум участникам, e-mail и внутренние id в ответах не передаются. Лимит 800 сообщений в сутки на аккаунт. Ограничения: нет групповых чатов, реакций, голосовых и push-уведомлений при закрытом приложении, нет сквозного шифрования (сообщения хранятся в Redis открытым текстом).


### Видео и уведомления в чате
- **Видео** (mp4/mov/webm, до 14 МБ) отправляются по частям и хранятся так же вечно, как фото; плеер без скачивания. Фото и постеры кэшируются на устройстве (Cache Storage), последние сообщения чата — в localStorage: чат открывается мгновенно после перезапуска.
- **Уведомления о сообщениях** (Web Push, без внешних зависимостей) включаются кнопкой в списке чатов. Нужны две переменные Vercel: `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY` (пара ключей P-256, base64url; необязательно `VAPID_SUBJECT`). На iPhone работает только из иконки «На экран Домой» (iOS 16.4+).

### Блокировка аккаунта
`BANNED_NICKS` (Vercel → Environment Variables, ники через запятую, например `amfx`). Заблокированный не может войти и работать: все запросы отвечают `banned`, приложение показывает чёрный экран со словом «хардес». Блокировка запоминается по аккаунту (смена ника не помогает). Чтобы **разблокировать**, уберите ник из `BANNED_NICKS` и сделайте Redeploy — запрет снимется автоматически при следующем запросе человека.

## Статус активности (только для одного аккаунта)

`ACTIVITY_ADMIN_USER_ID` (Vercel → Environment Variables) — постоянный внутренний ID (`sub`) аккаунта @kk1cher9. Узнать его: войдите под этим аккаунтом → Настройки → «Скопировать ID аккаунта». Только этот аккаунт получает точное время последнего визита любого пользователя (в шапке чата, списке чатов и `GET /api/dm?a=activity&nick=…`). Остальные: ничего (нет подписки друг на друга) либо грубый статус «был(а) недавно/сегодня…» только для взаимных подписчиков; запрос `a=activity` для них отвечает 404. Права проверяются на сервере по ID, а не по нику; ID нигде не попадает в клиентский код. Если переменная не задана — точное время не видит никто. Активность = серверное время последнего запроса (heartbeat раз в ~25–60 с пока приложение открыто); при выходе из аккаунта ставится метка «офлайн», «В сети» длится не дольше 70 с после последнего запроса.

## Профиль: стиль, заработок, бренды

Новые необязательные поля профиля (`fst`, `earn`, `earnPub`, `brands`) хранятся в том же JSON `wd:s:prof:<sub>` — миграция не нужна, старые профили работают как раньше. Частичное обновление профиля (например, только био) не стирает эти поля. «Статус заработка» виден другим только если владелец включил «Показывать в профиле» и не выбрал «Не указывать»; суммы и документы не запрашиваются.

## Удаление заблокированных аккаунтов

Только аккаунт `ACTIVITY_ADMIN_USER_ID`: Настройки → «Заблокированные аккаунты» → «Удалить…». Сначала показывается список (ник, посты, истории, чаты) без удаления, затем нужно подтвердить. Удаляются профиль, ник, аватар, посты, истории, подписки и **личные переписки** этого аккаунта (у собеседников они тоже исчезают). Сам запрет остаётся (`wd:s:ban:<sub>`), войти заново нельзя. Список берётся из `BANNED_NICKS` и из набора `wd:s:bans`. Данные гардероба (`wd:` ключи синхронизации) не трогаются.

## Редактор фото, видео-посты и репосты (Driply)

- **Посты на весь экран:** карточка занимает всю ширину экрана без боковых полей.
- **Редактор** (`editor.js`) открывается после выбора фото для поста или истории (и кнопкой «Редактор»): 10 фильтров с ползунком силы, текст (цвет, фон, перетаскивание, два пальца — размер и поворот), вещи из гардероба как наклейки на фото, GIF-наклейки. Фильтры, текст и вещи «запекаются» в картинку, GIF остаются отдельным слоем и продолжают двигаться. Слои можно открыть и править повторно до публикации.
- **«Во что я одет(а)»:** вещи с галочкой показываются полосой под фото (до 6 плиток) и дописываются в список вещей поста.
- **GIF:** свой файл (только `image/gif`, до 260 КБ, не более 3 своих) или поиск GIPHY — нужен `GIPHY_API_KEY` в Vercel (необязательно; ключ остаётся на сервере, браузер ходит через `GET /api/social?a=gifs`). В посте/истории сохраняются только ссылки на `media*.giphy.com`.
- **Видео в посте:** кнопка «Видео» в окне публикации, файл до 14 МБ (mp4/mov/webm) загружается кусками по 512 КБ без перекодирования, обложка — кадр из видео. Воспроизведение с поддержкой Range (работает в Safari).
- **Репосты:** кнопка в карточке чужого поста; репост появляется в вашем профиле и в «Подписках» у ваших подписчиков, автору приходит уведомление. Свой пост репостить нельзя; удалить репост — меню «⋯» на карточке. Удаление оригинала убирает и репосты.
- **Профиль:** вместо большой кнопки «Редактировать» — иконка карандаша справа, вместо надписи «Настройки» — три полоски слева.
- Новый сервис-воркер `wardrobe-v78` — после деплоя закройте и откройте приложение один раз.
- **Шрифты в редакторе:** 8 системных шрифтов для текста на фото/в истории (без загрузки из сети, запекаются в картинку).
- **Реакция на двойное касание в чате:** по умолчанию 👍, меняется в Настройки → «Реакция на двойное касание» (8 эмодзи); повторное двойное касание снимает реакцию.
